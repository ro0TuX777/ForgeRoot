# SAM Integration Responses for ForgeLedger Questionnaire

## 1. Agent Workflow & Use Case

- **Primary Workflows:** SAM (Small Agent Model) manages a federated compute economy across cross-platform nodes (Windows/Mac), performs autonomous load balancing, handles bulk document ingestion (with RAG vector retrieval), and executes cognitive loops such as memory clustering and synthesis (Dream Canvas). It also supports structured tool execution like ticket creation for governance.
- **Agent Autonomy:** High autonomy. Agents participate in autonomous compute load balancing and resource exchange within a peer-to-peer mesh. They utilize resource-aware model selection (e.g., dynamically downgrading from a 35B model to a 7B tool-capable model when resources are constrained) and execute autonomous governance tasks using the LIGAND Neuro-Stack Architecture.
- **Blast Radius:** Misallocation or exhaustion of compute resources across the federated mesh, pollution of the vector memory store (which holds 48,000+ files), hallucinated execution of governance tools (e.g., rogue ticket creation), and breaches of node isolation during peer-to-peer resource sharing.

## 2. Event Emission & Interception Points

- **Admission / Authentication:** We recently integrated the CONCORD v0.5.1 Governance Framework, which enforces a strict 11-stage deterministic admission pipeline. This serves as our primary interception point for incoming agent invocations.
- **Policy Evaluation:** Handled via our parallel "Agent Surface" and CONCORD runtime contracts, which manage secure, budget-governed autonomous execution. Resource monitoring is intercepted via the VAGUS component of our LIGAND architecture.
- **Model Inferences (LLM Calls):** We use a unified provider-agnostic Core Engine router (`BaseInferenceProvider`) for Ollama and llama.cpp. This router normalizes tool-calls and requests, making it an ideal centralized interception point for logging inference events.
- **Tool / API Execution:** Tool execution is funneled through the "Agent Surface" using structured tool-calling models (like Qwen2.5-7B-Instruct). 
- **Human-in-the-Loop (HITL):** Found primarily in our Bulk Document Ingestion interface (e.g., Manual Scan functionality) and UI-driven memory exploration features.

## 3. Data Sensitivity & Redaction

- **Data Classes:** Our `memory_store` vectors can contain highly sensitive ingested documents, including proprietary source code, internal system logs, and potentially PII. Additionally, we handle federated node configurations and cluster keys.
- **Redaction Capabilities:** While we have provider-hardened extraction, we do not currently have robust ingest-time redaction rules for our vector payloads. We will likely rely on ForgeLedger to classify and redact sensitive fields before they enter the evidence ledger.

## 4. Tenant Context & Isolation

- **Multi-Tenancy:** SAM operates as a decentralized, peer-to-peer mesh economy rather than a traditional multi-tenant SaaS. Nodes dynamically form clusters. 
- **Residency Requirements:** Data processing is local-first via Ollama/llama.cpp. Evidence logs will need to respect the distributed nature of the nodes, ensuring logs remain anchored to the local node's geographic footprint unless explicitly synchronized.

## 5. Security & Key Management

- **Secret Management:** Cluster keys and Ollama network bindings are dynamically generated and distributed without hardcoding by our cross-platform setup scripts (`setup_federation.py`). Models and agents manage configurations via YAML files.
- **Identity & RBAC:** We track actors using dynamically assigned node IDs across the federated mesh and agent profiles loaded from YAML configurations. Identity is verified at the cluster level via peer-to-peer cluster keys.

## 6. Compliance & Assurance Goals

- **Target Frameworks:** We are targeting the defense-ready architectural standards outlined in the ForgeRoot Control Plane Security Hardening addendum. Our goal is to address red-team concerns regarding latency, SPOF, evidence interoperability, and legacy system integration to secure Phase 2 prototyping funding.
- **Evidence Consumers:** Red-team auditors, internal compliance officers reviewing Phase 2 prototyping readiness, and peer node operators verifying compute economy transactions.
